# Humanize Korean — AI 한글 티 제거 오케스트레이터 (v2.0)

AI(ChatGPT·Claude·Gemini 등)가 쓴 한글 텍스트를 내용은 한 글자도 건드리지 않고 문체·리듬·표현만 자연스러운 한국어로 되돌리는 오케스트레이터.

## 트리거

다음 표현이 포함되면 이 스킬을 발동한다:
"AI 티 없애줘", "GPT 문체 제거", "사람이 쓴 것처럼 윤문", "번역투 제거", "AI 윤문", "humanize Korean", "AI 글 자연스럽게", "ChatGPT 티 제거", "AI 글 티 안 나게"

## Phase 0: 모드 결정

작업 시작 시 출력:
```
humanize-korean v2.0 — {fast|strict} 모드 / run_id: {YYYY-MM-DD-NNN}
```

### 모드 결정 규칙
- 사용자가 `--strict`·"정밀 모드"·"5인 파이프라인" 명시 → **strict**
- 입력 8,000자 초과 → **strict** (자동 승급 + 1줄 고지)
- 그 외 모두 → **fast (디폴트)**

### run_id 결정
- cwd 기준 `_workspace/{YYYY-MM-DD-NNN}/`에 폴더 생성.
- 당일 폴더가 없으면 NNN = 001. 있으면 마지막 NNN + 1.

## Fast 모드 (디폴트)

### Phase 1: 입력 저장
1. `_workspace/{run_id}/` 생성
2. 입력 텍스트를 `01_input.txt`에 저장
3. 첫 300자로 장르 자동 추정

### Phase 2: Monolith 호출
`humanize-monolith` 에이전트를 subagent로 1회 호출.

입력:
- input_path: `_workspace/{run_id}/01_input.txt`
- quick_rules_path: `.kiro/skills/humanize-korean/references/quick-rules.md`
- genre_hint: 칼럼 | 리포트 | 블로그 | 공적 | null

출력:
- `_workspace/{run_id}/final.md` — 윤문본 + HUMANIZE-SUMMARY 주석 블록

### Phase 3: 결과 전달
사용자에게 반환:
1. 한 줄 상태: `완료. 변경률 X% / 등급 Y / 자체검증 N/6 통과`
2. 핵심 카테고리 탐지 4~6건 (before → after)
3. 등급 B 이하면 strict 모드 안내

## Strict 모드 (`--strict` 또는 자동 승급)

### Phase A: 탐지
`ai-tell-detector` subagent 호출 → `02_detection.json`

### Phase B: 윤문 (최대 3회 루프)
`korean-style-rewriter` subagent 호출 → `03_rewrite.md` + `03_rewrite_diff.json`

### Phase C: 병렬 검증
두 subagent를 병렬 호출:
- `content-fidelity-auditor` → `04_fidelity_audit.json`
- `naturalness-reviewer` → `05_naturalness_review.json`

종합 판정 매트릭스:

| fidelity | naturalness | 종합 | 후속 |
|---|---|---|---|
| full_pass | accept / accept_with_note | **최종 승인** | Phase D |
| full_pass | rewrite_round_2 | **2차 윤문** | Phase B 재호출 |
| full_pass | rollback_and_rewrite | **롤백 후 재윤문** | 윤문가에 edit 롤백 지시 |
| conditional_pass | - | **롤백된 edit만 재시도** | Phase B 재호출 |
| fail | - | **전면 재작업** | Phase B 전면 재호출 |

최대 3회 후 미해결이면 `hold_and_report`로 사람 개입.

### Phase D: 최종 출력
1. `final.md`에 최종 윤문본 복사
2. `summary.md` 생성
3. 사용자에게 결과 + 등급 + 안내

## 부분 재실행 / 후속 명령

| 사용자 신호 | 처리 |
|---|---|
| "특정 카테고리만 다시" | strict 모드, 해당 카테고리 finding만 Phase B 재실행 |
| "이 문단만" | strict 모드, 해당 문단만 새 run_id |
| "2차 윤문" | 기존 run_id의 final.md를 새 입력으로 strict Phase B |
| "윤문 강도 조정" | strict 모드, min_severity 변경 후 Phase A부터 |

## 옵션 (자연어로)

- `장르: 칼럼|리포트|블로그|공적` — 장르 명시
- `강도: 보수|기본|적극` — 윤문 강도
- `최소심각도: S1|S2|S3` — 탐지 임계값
- `--strict` — 5인 파이프라인 강제

## 4대 철칙

1. **의미 불변** — 사실·주장·수치·고유명사·직접 인용 100% 보존.
2. **근거 기반** — 탐지된 span에만 수술적 수정.
3. **장르 유지** — 칼럼→문학, 리포트→에세이 이탈 금지.
4. **과윤문 금지** — 변경률 30% 초과 경고, 50% 초과 강제 중단.

## Do-NOT List (탐지·윤문 대상 제외)

- 수치·단위·날짜
- 고유명사·인명·제품명·모델명
- 큰따옴표 내부 직접 인용
- 법률·규정 조문
- 영어 약어(LLM·GPU·MCP·API 등 업계 표준)
